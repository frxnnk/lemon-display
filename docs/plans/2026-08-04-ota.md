# OTA por WiFi — plan de implementación

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Que el aparato pueda actualizarse por WiFi desde el proxy, con un
botón en la pantalla de configuración, validando el certificado del servidor y
con rollback automático si el firmware nuevo no consigue red.

**Architecture:** Dos endpoints nuevos en el proxy Go detrás del guard que ya
existe, y un módulo `src/ota_ferced.{h,cpp}` en el firmware que compara
versiones, descarga a la partición inactiva con `Update.h` y confirma el
arranque recién cuando el firmware nuevo demuestra que tiene red.

**Tech Stack:** Go (proxy), C++/Arduino + `Update.h` + `esp_ota_ops.h`
(firmware), mbedTLS con CA embebida.

Diseño validado: `docs/plans/2026-08-04-ota-design.md`

---

## Notas antes de empezar

**El firmware no tiene framework de tests.** El proxy sí, y ahí los tests van en
serio. Del lado del aparato la verificación es empírica y está en la Task 6.

**Habilitar esto requiere un flasheo por USB.** Es la última vez que hace falta,
pero hace falta.

**El certificado NO se inventa.** Se baja de la fuente oficial. Hay que embeber
**las dos** raíces de Let's Encrypt, X1 (RSA) y X2 (ECDSA): el servidor sirve una
cadena u otra según lo que negocie el cliente, y mbedTLS del ESP32 negocia
distinto que un cliente de escritorio. Medido el 2026-08-04, un cliente Windows
recibe la cadena que termina en **ISRG Root X2**.

// proxy/internal/api/firmware_test.go
package api

import (
	"encoding/json"
	"net/http"
	"net/http/httptest"
	"os"
	"path/filepath"
	"testing"
)

func dirConBinario(t *testing.T, contenido string) string {
	t.Helper()
	dir := t.TempDir()
	if err := os.WriteFile(filepath.Join(dir, "firmware.bin"), []byte(contenido), 0o644); err != nil {
		t.Fatal(err)
	}
	if err := os.WriteFile(filepath.Join(dir, "version.txt"), []byte("1.2.3\n"), 0o644); err != nil {
		t.Fatal(err)
	}
	return dir
}

func TestFirmwareInformaVersionTamanoYHash(t *testing.T) {
	fw := &Firmware{Dir: dirConBinario(t, "hola")}
	rec := httptest.NewRecorder()
	fw.serveMeta(rec, httptest.NewRequest(http.MethodGet, "/v1/firmware", nil))

	if rec.Code != http.StatusOK {
		t.Fatalf("status = %d", rec.Code)
	}
	var m struct {
		Version string `json:"version"`
		Size    int64  `json:"size"`
		SHA256  string `json:"sha256"`
	}
	if err := json.Unmarshal(rec.Body.Bytes(), &m); err != nil {
		t.Fatalf("respuesta no es JSON: %v", err)
	}
	if m.Version != "1.2.3" {
		t.Errorf("version = %q", m.Version)
	}
	if m.Size != 4 {
		t.Errorf("size = %d, quiero 4", m.Size)
	}
	// sha256 de "hola"
	const want = "b221d9dbb083a7f33428d7c2a3c3198ae925614d70210e28716ccaa7cd4ddb79"
	if m.SHA256 != want {
		t.Errorf("sha256 = %q", m.SHA256)
	}
}

func TestFirmwareSirveElBinarioConLargoDeclarado(t *testing.T) {
	fw := &Firmware{Dir: dirConBinario(t, "hola")}
	rec := httptest.NewRecorder()
	fw.serveBin(rec, httptest.NewRequest(http.MethodGet, "/v1/firmware/bin", nil))

	if rec.Code != http.StatusOK {
		t.Fatalf("status = %d", rec.Code)
	}
	if rec.Body.String() != "hola" {
		t.Errorf("cuerpo = %q", rec.Body.String())
	}
	// Sin Content-Length el HTTPClient del ESP32 recibe chunked y Update.h no
	// sabe cuanto espera. Es la misma trampa que ya mordio al feed.
	if rec.Header().Get("Content-Length") == "" {
		t.Error("falta Content-Length")
	}
}

func TestFirmwareSin404CuandoNoHayBinario(t *testing.T) {
	fw := &Firmware{Dir: t.TempDir()}
	rec := httptest.NewRecorder()
	fw.serveMeta(rec, httptest.NewRequest(http.MethodGet, "/v1/firmware", nil))
	if rec.Code != http.StatusNotFound {
		t.Errorf("status = %d, quiero 404", rec.Code)
	}
}

func TestFirmwareDeshabilitadoSinDir(t *testing.T) {
	fw := &Firmware{Dir: ""}
	rec := httptest.NewRecorder()
	fw.serveMeta(rec, httptest.NewRequest(http.MethodGet, "/v1/firmware", nil))
	if rec.Code != http.StatusNotFound {
		t.Errorf("sin FIRMWARE_DIR tiene que dar 404, dio %d", rec.Code)
	}
}

### Task 2: Las raíces de Let's Encrypt

**Files:**
- Create: `src/data/le_roots.h`
- Create: `tools/fetch_le_roots.py`

**Step 1: Bajar los certificados de la fuente oficial**

Un script que baje de `https://letsencrypt.org/certs/isrgrootx1.pem` y
`https://letsencrypt.org/certs/isrg-root-x2.pem` y genere el header con las dos
concatenadas en un `const char LE_ROOTS[] PROGMEM`.

**No escribir el PEM a mano ni de memoria.** Un certificado mal transcripto
falla en tiempo de ejecución con un error de TLS opaco.

**Step 2: Verificar contra el servidor real**

```bash

```

### Task 5: La red de rollback

**Files:**
- Modify: `src/ferced_main.cpp`

**Step 1: Averiguar si Arduino ya marca la app como valida**

Esto es lo primero y condiciona todo lo demás. Buscar en el framework llamadas a
`esp_ota_mark_app_valid_cancel_rollback`:

```bash
grep -rn "mark_app_valid" C:/Users/Ferced/.platformio/packages/framework-arduinoespressif32/
```

Si Arduino la llama sola al arrancar, **el rollback queda anulado** y hay que
ver cómo diferirlo. Si no la llama, seguir al paso 2.

**Step 2: Confirmar recien cuando el firmware demuestra que sirve**

En `refreshFeed()`, cuando el resultado sea `FEED_UPDATED` por primera vez tras
un arranque, llamar a `esp_ota_mark_app_valid_cancel_rollback()`.

No al bootear: un firmware que arranca pero se queda sin red es justamente el
caso que el rollback tiene que atrapar.

**Step 2: Camino feliz**

2. Long press, tocar «Buscar actualización».
3. Ver el progreso llegar a 100 y el aparato reiniciar.
4. Volver a entrar a configuración: la versión y el commit tienen que ser los
   nuevos.

**Step 3: El rollback, a propósito**

Esta prueba es la que hace que la red de seguridad deje de ser una suposición.

1. Compilar un firmware con versión mayor y el SSID de WiFi roto a propósito.
2. Subirlo y aplicarlo por OTA.
3. El aparato tiene que arrancar, no conseguir red, y **volver solo al firmware
   anterior** en el siguiente reinicio.
4. Confirmar mirando la versión en la pantalla de configuración.

Si esto no pasa, el OTA es más peligroso que el USB y hay que frenar.
